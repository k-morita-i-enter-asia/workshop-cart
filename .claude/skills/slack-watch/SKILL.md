Slackチャンネルの新着投稿を確認し、**機能追加の要望だけ**に対応する。それ以外は何もしない。

対象チャンネルは `ai-driven-development-study-group`（ID: `C0BF9H24JTG`）。
状態ファイルは `.claude/slack-watch-state.json`。

## 絶対に守ること

このスキルは無人で繰り返し実行される。次の制約を破ると、同じ投稿に何度もPRを立てる暴走になる。

1. **状態ファイルの更新は必ず最後に行う。** 途中で失敗した場合は更新しない（次回リトライさせる）。
2. **1回の実行で着手するのは最大1件。** 複数あれば古いものを1件だけ処理し、残りは次回に回す。
3. **PRは必ず draft で作成する。** `main` への直接 push とマージは行わない。
4. **機能追加の要望だと確信できない投稿は、すべて対象外として何もしない。**
5. **Slackへの投稿は該当スレッド内のみ。** `@channel` と `@here` は使わない。
6. **顧客のメールアドレス・氏名・住所を、Slack投稿にもログにも含めない。**

## 手順

### 1. 状態を読む

`.claude/slack-watch-state.json` を読み、`last_ts` と `handled` を得る。
ファイルが無い場合は作成せず、未初期化であることを報告して終了する。

### 2. 新着投稿を絞り込む

`slack_get_channel_history` で `channel_id: "C0BF9H24JTG"`、`limit: 30` を取得し、次を捨てる。

- `ts` が `last_ts` 以下のもの
- `ts` が `handled` に含まれるもの
- `subtype` があるもの（`channel_join` などのシステム投稿）
- `bot_id` があるもの、または自分自身の投稿

### 3. 機能追加の要望かどうかを判断する

残った投稿それぞれについて、**このリポジトリへの機能追加・変更の要望か**だけを判断する。

要望と見なすのは、追加してほしい振る舞いが具体的に書かれているものだけ。
連絡・雑談・資料共有・会議案内・質問・バグ報告は、すべて対象外。

判断に迷ったら対象外にする。実装しない方が安全側。

対象が1件も無ければ、`last_ts` を取得した中の最大の `ts` に更新して**手順6**へ進む。

### 4. 1件だけ選ぶ

対象のうち `ts` が最も古い1件を選ぶ。選ばなかったものは `handled` に**入れない**（次回処理する）。

選んだ投稿に `slack_add_reaction` で `eyes` を付け、着手を可視化する。

### 5. 実装して draft PR を作る

1. `git switch main && git pull` で最新にする。
2. `git switch -c feat/<短い英語の要約>` で作業ブランチを作る。
3. 実装する。API応答を変更する場合は `CLAUDE.md` の規約に従う。
   - 金額フィールドは cent 単位の整数、名前は `Cents` で終わらせる
   - 注文一覧APIの応答を変えたら `docs/openapi.yaml` の schema と required を両方更新する
   - 既存フィールドの意味と名前は変えない
   - 名前付きexportのみ使う
4. Vitestでテストを追加する。API応答を変えた場合は、通常の配送料・配送料ゼロ・顧客情報を含まないこと の3ケースを確認する。
5. `npm test` と `npm run build` を実行する。
6. **どちらかが失敗したら、PRを作らずスレッドに失敗内容を報告して終了する。** 状態ファイルは更新しない。
7. 成功したらコミットして push し、`gh pr create --draft` でdraft PRを作成する。本文は `prepare-pr` スキルのテンプレートに従う。
8. `slack_reply_to_thread` でスレッドにPRのURLと変更の要約を1〜3行で返信し、レビュー依頼であることを明記する。
9. 投稿に `slack_add_reaction` で `white_check_mark` を付ける。

### 6. 状態を更新する

`.claude/slack-watch-state.json` を次の形式で書く。

```json
{
  "channel_id": "C0BF9H24JTG",
  "last_ts": "<今回確認した中で最大のts>",
  "handled": [{ "ts": "...", "pr": "#12" }]
}
```

`handled` は末尾に追記し、100件を超えたら古いものから削る。

PRを作った場合は、状態ファイルの変更もそのPRのブランチに含める。
PRを作らなかった場合はコミットせず、ローカルの変更のままにする。

### 7. 結果を報告する

```
確認: <件数>件の新着投稿
要望: <n>件
対応: <作成したPR、または「対応不要」>
次回: last_ts = <値>
```
